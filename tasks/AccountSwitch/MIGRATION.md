# 从独立 OAS-Alt 迁回原 OASX

迁移工具只处理“小号切换”配置与断点，使用原 OAS 的 Python 环境，不依赖独立工具或它的界面。维护分支仅为用户 fork 的 `dev`，不向上游提交 PR。

先退出独立工具及其后端，再关闭目标原 OASX，避免两个程序继续改写进度或配置。保留独立工具的整个 `data` 文件夹。源目录始终只读；目标配置须放在源目录之外。

在原 OAS 根目录先预览，路径替换为本机实际位置：

```powershell
python -m tasks.AccountSwitch.migrate_alt --source-db "D:\OAS-Alt\data\oas-alt.db" --target-config "config\小号.json"
```

默认只输出迁移条数与说明，不修改配置。确认目标文件后加 `--apply`：

```powershell
python -m tasks.AccountSwitch.migrate_alt --source-db "D:\OAS-Alt\data\oas-alt.db" --target-config "config\小号.json" --apply
```

迁移后的本任务 `scheduler.enable`、安卓 `routine_enable`、苹果 `ios_daily_enable` 和旧版手动自动勾协均关闭。导入不等于开始执行；先在原 OASX 核对账号、平台、各自时间及大号/好友，再手动开启需要的例程和任务调度。其它 OAS 任务的开关保持原值。

账号顺序、`#别名`、各平台模式、逐号目标、苹果时间、三组随机偏移、觉醒层数/目标/麒麟及免费日常选项会迁入。原 OASX 用 JSON 多行字段显示逐号模式与目标，不添加独立桌面界面。

两个目标在新配置中独立：勾协接收大号不自动作为协战借用好友。旧工具的空协战默认曾沿用全局接收大号，因此迁移会显式写入该全局协战好友，保留旧工具当时的有效行为；逐号明确配置仍优先。

源工具的模拟器路径、实例索引与结束动作不能直接等价替换原 OAS 的全局启动配置，原始值会归档。默认不改原 OAS 的设备设置。若目标配置专用于这些小号，可额外加 `--map-device`，只迁入 ADB 地址和非空游戏包名。实例索引不等于窗口名称；启动与收尾仍使用原 OAS 的设置。

## 断点与历史保留方式

- Android/iOS 按规范化 SDK 账号与平台分别保存；iOS 的原 `ios_*` 断点转换为同一套日常进度字段。
- 同日已有完成标志取并集，觉醒计数取较大值，不累加重复记录；目标已有较新日期时不回退。重复执行迁移不会重复计胜。
- “觉醒总已确认”“协战界面观察数”“有记录的脚本胜场”分别保存。观察数可能包含先前脚本战斗，不能简单相加，也不会把观察到的14次当成脚本打了14次。缺少活动历史时，脚本胜场只保留已知下界，不推算未知场次。
- 日常只有完成布尔、没有准确时间时，保存为 `daily_confirmed`。只有真实活动记录已有时间时才填 `daily_record`，不编造完成时间。
- 勾协按刷新时段与接收方保留配额、原派发账号、待确认内容与已检查账号。两边存在互相冲突的待确认派发时会拒绝覆盖，需先核对。
- 随机样本与重试元数据保留；运行中服务的武装标记不迁入，避免重新开启后立即补跑旧轮次。

每次正式写入前，在目标配置旁创建私有的 `<配置名>.alt-migration-<时间>-<随机标识>` 文件夹：

| 文件 | 内容 |
| --- | --- |
| `target.before.json` | 目标配置写入前的完整原始字节，可用于恢复 |
| `alt-source.sqlite3` | 包含已提交 WAL 断点与全部历史的完整一致 SQLite 快照 |
| `source-values.json` | 全部原始 KV，包括未直接映射的设置与调度信息 |
| `activity.jsonl` | 全部执行事件，不受接口默认500条限制 |
| `migration-report.json` | 迁移说明、数量和源文件校验值 |

原 OAS 配置只保存可执行断点，不把全部历史塞入配置 JSON。原 OASX 日志页不会伪造或自动回放独立工具的旧日志；旧历史通过上述 SQLite/JSONL 私有归档完整保留。归档含账号及执行记录，不应提交到仓库或上传发布包。

读取过程中发现源 DB/WAL 或目标配置被其它程序改动时，工具会停止，保留原文件供核对。不要在旧工具仍继续跑任务时迁移。
