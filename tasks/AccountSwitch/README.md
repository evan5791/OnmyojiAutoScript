# 同区小号日程与切换

所有小号沿用上次登录的区服，不选区、不逐号填写角色名。账号列表每行一个网易登录列表中显示的账号，例如掩码手机号 `153****4444` 或邮箱 `example@163.com`，支持十个及以上账号；空行忽略，重复账号只执行一次。新增小号先在模拟器手动登录一次，再把账号加一行。

## 每天两轮

| 时段 | 默认时间 | 每个小号执行内容 |
| --- | --- | --- |
| 06:00 刷新后的白天轮次 | 17:00 | 只寻找勾玉协作，邀请同区大号并完成该悬赏。一个小号完成本轮勾协后停止查找其他小号。 |
| 18:00 刷新后的晚间轮次 | 20:00 | 每日琐事 → 本轮勾协（若尚未完成）→ 单人觉醒。后续小号仍做琐事、觉醒，跳过已经满足的勾协。 |

两个刷新时段各给大号完成一次勾协，每天共两次。只追踪并执行选中的一个勾协，其他悬赏不做。时间都可在 OASX 修改；白天时间须在06:00至18:00之前，晚间须在18:00之后。跨过午夜仍属于同一个18:00勾协刷新轮次，但日常、苹果登录和觉醒次数按零点切换为新一天，昨天的胜场不抵扣今天。

## OASX 配置

在「肝帝专属 → 小号切换」中：

- 填写账号列表；纯切号使用全局 Android/iOS 选择，日程使用下文逐账号平台模式。
- 打开需要的安卓/苹果日程开关并启用本任务调度。游戏未运行时，小号任务会先启动游戏，再校验账号并登录，无需为此开启「游戏重启」。若启用了「游戏重启」，专用小号配置会将它的独立日程推迟，按小号实际计划恢复游戏。
- 「邀请好友昵称」填写同区大号，例如 `5791`。大号须在线并接受勾协；本任务不控制大号客户端。日程模式留空时先复用「悬赏封印」好友昵称，仍为空则使用 `5791`。
- 白天、晚间默认分别17:00和20:00。未完成部分默认10分钟后重试，不跨越对应的06:00/18:00刷新边界。
- 觉醒默认1层、每号14次，可设置1至10层和次数。全程保持阵容未锁定，每场挑战都进入准备页，用借用卡的完整 `N/15`、出战标记和跨帧浅金底色确认已上阵；不以某个式神头像作为固定条件。只按获胜且结算完成的场次记录；不额外领取每日或成就奖励。
- 「小号庭院事务」「小号收取邮件」可分别开关。其余每日琐事复用同一配置中的「每日琐事」选项，但完成记录按小号单独保存。不会自动打开购买体力、抽卡等未开启的选项。

账号识别不稳定时，可按 `账号#识别别名1#识别别名2` 增加 OCR 别名。昵称精确匹配，例如 `5791` 不会匹配 `15791`，邀请只查同区好友。

SDK 将长邮箱显示为省略号时，保留完整邮箱作为账号，将截图中的完整显示文本（含省略号）加入识别别名。别名仍须精确匹配，不将任意邮箱前缀视为登录成功。

关闭每日流程后仍可手动纯切号；只保留一行即可切指定账号。「手动切号后自动勾协」仅用于此手动模式，与每日流程独立。

## 进度与恢复

日常完成记录、觉醒已完成次数以及每个刷新时段的勾协进度保存在当前配置的隐藏 `account_switch.runtime` 中，重启后保留。每个账号及Android/iOS分别记录。晚间重试只补未完成的步骤和剩余觉醒次数，不重复其他小号已经完成的日常。

找到勾协、发出邀请和完成悬赏是不同状态。只有观察到该唯一追踪勾协的完成奖励，才记本轮完成。已发出的勾协由原小号继续，不允许另一小号重复派发。若中断恰好发生在发出邀请的一刻，无法确认是否发出时，会保留该小号和记录，日志提示核对；不会自动重发。登录失效、验证码等情况仍需手动处理。

日程等待重试不会累计成游戏崩溃失败。子流程的配置和调度与独立「每日琐事」「觉醒」「悬赏封印」任务隔离。

## 从独立工具迁回

独立 OAS-小号 / OASX2 已停止开发。本模块直接运行在原 OAS/OASX 中，复用原 MuMu/游戏管理、Page 路由、RuleImage/RuleOcr 与共享 OCR，不加载 CustomTkinter，不启动独立工具或第二套识别服务。

新增配置仍由原 OASX 动态表单展示：

- 安卓开关「启用小号每日流程」，苹果使用独立「苹果日常」开关与执行时间。苹果只日常或仅登录，不做勾协、探索、觉醒。
- 「逐账号平台模式」是 JSON 文本，例如 `{"example@163.com":{"android":"plan","ios":"daily"}}`。安卓支持 plan/login/off，苹果支持 daily/login/off；留 `{}` 使用完整安卓计划和苹果日常。平台开关分别控制是否调度该平台。
- 「逐账号大号与协战」分别配置 `jade_receiver` 与 `assist_friend`。例如 `{"example@163.com":{"jade_receiver":"接收大号","assist_friend":"借用好友"}}`。两者独立，留空沿用各自全局配置；协战目标未填写且无法确认时会待处理，不随意换用其他好友。
- 安卓白天、晚间和苹果日常各自设置 0–180 分钟随机偏移，默认 ±15。每个时段只保存一次实际时间，重启不重抽。双方都已到点时按平台优先级运行，每个平台按账号列表顺序完成。
- 启动原 OAS 服务时，先等待未来的计划时间，不立即补跑过去时段。小号全部完成后沿用原 OAS 空闲策略；失败、待处理或中断时保留模拟器与断点。原壳底层明确要求人工接管的错误仍需处理。
- 觉醒前核对指定好友、出战状态和两处每日次数，一致才采信。14/15 或15/15跳过；不足14结合本地确认进度补足，不把不明确的计数当0。上阵由原识图/页面状态确认，拖动由匹配到的卡片位置发出；没有照搬独立版盲点/盲按返回逻辑。

原 OASX 的日志页继续查看每日运行日志。每号事件另追加到 `log/account-switch/配置名/日期.jsonl`，按北京时间零点分日，包含登录、日常子项、勾协检查/派发、真实胜场、跳过和异常。勾协日志同时保留06:00/18:00刷新轮次。观察到14次与程序实际打出14场分别保存；不会把旧记录伪造为新操作。

关闭独立工具和目标 OAS 配置后，先预览迁移：

```powershell
python -m tasks.AccountSwitch.migrate_alt --source-db "D:\OAS-Alt\data\oas-alt.db" --target-config "config\alts.json"
```

确认预览后加 `--apply`。先准备一个有效原 OAS JSON 配置作为目标；建议复制原配置或模板为专用小号配置。`--map-device` 可迁移 ADB 地址和非空游戏包名，默认保留目标设备设置。只按端口识别设备仍需遵守原 OAS 自身的 MuMu 路径/窗口设置，不能把独立版空窗口参数等同于原壳所有连接方式。

迁移会先备份目标，再在目标旁的 `*.alt-migration-*` 私有目录归档完整 SQLite、KV 和旧历史。源数据库及 WAL 只读复制，不修改、不删除。目标中的其他任务配置保持原样；小号 scheduler、安卓和苹果开关默认关闭，避免导入即运行。完整旧历史在归档中保留，不会自动重放到原日志页。旧布尔断点继续跳过已完成步骤，不捏造完成时间。

归档和迁移后的个人配置不得提交到 GitHub；迁移目录已经加入忽略规则。
